Why make skills portable?

These workflows started in Claude Code. Now they work with other assistants too.

Platform neutral

Plain Markdown with YAML frontmatter. No platform hooks, no CLI lock-in.

From the source

These prompts come from the source. They are the same patterns teams already use.

One-command installation

Add one skill or the whole collection with a single command.

Layered detail

Core instructions stay in the main SKILL.md file. Detailed guides and helper scripts live in subdirectories.

22 specialized personas

Security reviews, PR toolkits, commit helpers, and more. Each skill does one thing well.

Faithful ports

The workflow logic stays intact. Only the syntax is adapted for other assistants.

Standard SKILL.md format

Each skill is a directory with a SKILL.md file. YAML frontmatter carries the metadata; the body holds the instructions. Both you and your assistant can read it.

No proprietary format means you can open, edit, or version these files like any other Markdown.

Explore All Skills
skills/feature-dev/SKILL.md 
---
name: feature-dev
description: |
  7-phase guided feature development:
  Discovery → Exploration → Clarifying
  Questions → Architecture Design →
  Implementation → Quality Review → Summary
---

# Feature Development Skill

## Phase 1: Discovery
- Analyze requirements and constraints
- Identify stakeholders and success criteria

## Phase 2: Exploration
- Research existing solutions
- Map technical dependencies

## Phase 3: Architecture Design
- Propose system structure
- Define interfaces and data flow

## Phase 4: Implementation
- Write code with progressive disclosure
- Test and iterate

## Phase 5: Quality Review
- Self-review against acceptance criteria
- Refactor and optimize
